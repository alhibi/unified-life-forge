# إعادة بناء قارئ SmartHub على مبادئ ReadYou وCapy Reader

## الهدف
تحويل «إطلاع» إلى قارئ سريع وموثوق يعمل محلياً أولاً، يتزامن بأمان، يعرض الأرشيف كاملاً، ويشرح فشل كل مصدر بوضوح — مع الحفاظ على الهوية العربية والتصميم الحالي.

> سنقتبس الأنماط والسلوكيات فقط. لن ننسخ كود المشروعين حرفياً لأن ترخيصهما GPL ولأن أجزاء كبيرة منهما خاصة بـAndroid.

## ما أثبته التحليل
- القارئ الحالي غني وظيفياً، لكنه يعرض إعدادات أوفلاين بينما طبقة التخزين المحلية معطلة بالكامل.
- القائمة السحابية تتوقف عند 300 مقال رغم أن الواجهة توحي بأرشيف كبير.
- نتيجة التحديث قد تظهر في الذاكرة ثم تختفي بعد إعادة التحميل عند استعمال المسار الاحتياطي.
- المحتوى الكامل المستخرج يُفقد بعد إعادة تحميل الصفحة ويُستخرج من جديد.
- منطق الاتصال بالبيانات موزع خارج نقطة الوصول المخصصة، ما يصعّب ضمان الأخطاء والسباقات.
- المجلدات وبعض التفضيلات محلية فقط، بينما الاشتراكات وحالة القراءة والحفظ سحابية.
- لا توجد اختبارات كافية لقلب التحديث والدمج رغم أنه أكبر وأخطر جزء.

## التنفيذ المتدرج

### 1. أساس محلي حقيقي وآمن
- استبدال طبقة الأوفلاين المعطلة بقاعدة IndexedDB فعلية عبر Dexie.
- تخزين نسخة قائمة خفيفة، ومحتوى المقال الكامل، ووقت الحفظ، وآخر وصول، وحالة اكتمال المحتوى.
- عزل البيانات حسب الحساب ومنع ظهور بيانات حساب سابق بعد تسجيل الخروج.
- تنفيذ عمليات batch ذرية، فحص صحة، تقدير مساحة، تنظيف، واحتفاظ بالمحفوظات دائماً.
- تشغيل الحفظ الفوري عند فتح المقال أو حفظه، مع استعادة فورية عند غياب الشبكة.

### 2. كاش الصور وواجهة التخزين الصادقة
- استبدال عامل الخدمة القاتل بعامل محدود للصور المطلوبة فقط، دون اعتراض طلبات التطبيق العامة.
- تفعيل أوامر precache / clear / estimate المستخدمة حالياً.
- احترام Data Saver والاتصال البطيء وتفضيل المستخدم.
- تحديث شاشة التخزين لتعرض أرقاماً حقيقية وحالات unsupported/quota/error بوضوح.

### 3. مسار بيانات موحد
- نقل كل قراءة لجداول المقالات واستدعاءات وظائف القراءة إلى `api.ts`.
- إضافة Zod للتحقق من استجابات RSS والاستخراج والبحث قبل دخولها إلى الحالة.
- إزالة الاستدعاءات المباشرة المتناثرة وإصلاح `as any` في تفضيلات القائمة.
- توحيد أخطاء الشبكة إلى حالات typed: اتصال، مصدر محظور، تنسيق غير صالح، مهلة، حد موارد، وإلغاء طبيعي.

### 4. تحديث حتمي قابل للاستئناف
- بناء منسق تحديث بصف انتظار لكل مصدر: queued → fetching → stored → failed.
- تثبيت حد الدفعة عند 3 في مصدر واحد مشترك، مع تزامن محدود وbackoff وjitter وإلغاء عند مغادرة الصفحة.
- حفظ حالة كل مصدر وآخر نجاح/فشل ووقت المحاولة، وعدم اعتبار المصدر الخالي فشلاً تلقائياً.
- ضمان أن كل نتيجة ناجحة تُخزّن قبل إعلان النجاح، بما فيها المسار الاحتياطي.
- منع التحديثات المتداخلة لنفس المصدر وتوحيد الطلبات المتكررة.

### 5. أرشيف كامل وصفحات بالمؤشر
- استبدال حد 300 باستعلامات cursor على `(pub_date, id)` مع تحميل تدريجي.
- إبقاء أول شاشة سريعة من IndexedDB ثم دمج الصفحة السحابية دون قفز أو تكرار.
- فصل «بيانات المقال» عن «حالة المستخدم» في الحالة المحلية، مع إبقاء الجداول الحالية سحابياً لتجنب هجرة خطرة غير لازمة.
- جعل الفلاتر والترتيب والمجلدات تستخدم مفتاح استعلام واحداً typed، على نمط ReadYou/Capy.

### 6. المقال الكامل واستخراج المحتوى
- تخزين نتيجة الاستخراج محلياً فوراً مع metadata عن الجودة/المصدر/وقت الاستخراج.
- إعادة استخدام النسخة المخزنة وعدم تكرار الاستخراج بعد كل reload.
- إبقاء الاستخراج اختيارياً لكل مصدر، مع وضع sticky full-content وتراجع واضح إلى ملخص RSS والرابط الأصلي.
- الحفاظ على الصور داخل الفقرات، الجداول، الاقتباسات والوسائط المسموحة، مع sanitization واختبارات fixtures لمواقع عربية وأجنبية.

### 7. المصادر والمجلدات وOPML
- تحسين اكتشاف المصدر بالتسلسل: RSS/Atom مباشر → روابط `<link>` → روابط الصفحة → تخمينات معروفة.
- تقرير تقدم استيراد OPML ومخرجات: أضيف/مكرر/غير صالح/فشل، بدلاً من نتيجة إجمالية مبهمة.
- حفظ بنية المجلدات ذات المستوى الواحد بوضوح، مع مزامنتها عبر الحساب في مرحلة قاعدة بيانات منفصلة وآمنة.
- إعدادات لكل مصدر: تفعيل، جلب كامل، احتفاظ، إشعارات، فتح أصلي، وتحديث يدوي.

### 8. تجربة القراءة الكثيفة الهادئة
- الحفاظ على القائمة الافتراضية الحالية، مع أوضاع مريح/مضغوط/بطاقات حقيقية ومتسقة.
- إبقاء السحب للقراءة/الحفظ، ووضع ما فوق/تحت كمقروء، والقراءة أثناء التمرير.
- إضافة مؤشرات مفيدة فقط: محفوظ محلياً، محتوى كامل/جزئي، آخر تحديث، وفشل المصدر.
- عدم إضافة زخرفة أو ازدحام؛ كل حالة loading/empty/offline/error تحجز نفس المساحة ولا تسبب قفزاً.

### 9. الاختبارات والتحقق قبل كل انتقال
- اختبارات Dexie: ترقية القاعدة، batch، dedupe، account isolation، quota، retention، وحفظ الصور.
- اختبارات منسق التحديث: فشل دفعة جزئياً، انقطاع/عودة الشبكة، إلغاء، تزامن، وعدم فقد النتائج.
- اختبارات pagination: عدم التكرار أو الإسقاط عند تساوي التواريخ وتغير الفلاتر.
- اختبارات OPML fixtures واستخراج المقال والصور وحالات الخطأ.
- سيناريوهات Playwright: فتح أوفلاين، إضافة مصدر، إعادة تحميل، استيراد OPML، تمرير أرشيف طويل، وتبديل حساب.
- تشغيل فحص المشروع الكامل بعد كل مرحلة؛ لا تنتقل المرحلة التالية إذا انخفضت موثوقية الحالية.

## ترتيب التسليم
1. التخزين المحلي + الاختبارات.
2. كاش الصور وشاشة التخزين.
3. توحيد API ومنسق التحديث.
4. pagination والأرشيف.
5. الاستخراج وOPML وإعدادات المصدر.
6. الصقل النهائي وتجارب الهاتف الفعلية.

## حدود مقصودة
- لا إضافة خدمات Feedbin/FreshRSS/Miniflux في هذه المهمة؛ نأخذ معمارية المزودات فقط كي تصبح إضافتها لاحقاً آمنة.
- لا نسخ Compose أو WorkManager أو Android notifications؛ البدائل ستكون Web/PWA وعمليات الخلفية الحالية.
- لا إعادة هيكلة عامة لبقية `src/features` ولا تغيير هوية التصميم خارج تطبيق القراءة.
- أي تعديل قاعدة بيانات سيأتي في migration مستقل مع الصلاحيات وRLS والاختبارات، ولن يُخلط مع إعادة التخزين المحلي.
