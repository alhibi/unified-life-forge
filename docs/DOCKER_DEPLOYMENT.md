# دليل تشغيل ونشر التطبيق باستخدام حاويات Docker وخادم Nginx

يوفر مشروع **SmartHub** بنية تحتية برمجية متكاملة لبيئة الإنتاج تعتمد على الحاويات (Containerization) لضمان أقصى درجات الاستقرار، الأمان، والأداء.

يتم البناء والتشغيل عبر آلية **البناء متعدد المراحل (Multi-stage Build)** باستخدام **Bun** لمرحلة البناء، وخادم **Nginx Alpine** مهيأ كأصل حماية (Security Hardened) ومسؤول عن تقديم الملفات بجودة وأداء فائقين.

---

## 🏗️ التصميم البنيوي والهندسي للملفات

1. **مرحلة البناء (Stage 1: Builder)**:
   - تستند على صورة `oven/bun:1.2-alpine` لسرعة التحميل والتثبيت.
   - تقوم بتثبيت الاعتماديات بدقة عبر `bun install --frozen-lockfile` لضمان مطابقة حزم الإنتاج تماماً لبيئة التطوير.
   - تقوم ببناء الأصول المحسنة في مجلد `dist/`.

2. **مرحلة التشغيل (Stage 2: Runner)**:
   - تستند على صورة `nginx:1.27-alpine` الخفيفة والمستقرة.
   - **التوجيه الذكي (SPA Routing)**: تم ضبط خادم Nginx لتوجيه جميع الطلبات تلقائياً إلى `index.html` لمنع حدوث أخطاء `404 Not Found` عند تحديث الصفحة يدوياً (Refresh) على أي مسار داخلي.
   - **تقليص الصلاحيات (Non-root Execution)**: تم نقل ملكية جميع ملفات التشغيل وصلاحيات الكتابة إلى المستخدم المحدود `nginx` (غير الصلاحي / Unprivileged) للوقاية من ثغرات هروب الحاوية (Container Escape)، والتشغيل آمن كلياً على المنفذ `8080`.
   - **التحقق من صحة الخادم (Healthcheck)**: تم تزويد الحاوية بفحص صحة مدمج يراقب جاهزية الخادم كل 30 ثانية.

---

## 🛡️ ميزات الحماية الفائقة المدمجة في Nginx

تم تفعيل الترويسات الأمنية الصارمة (Strict Security Headers) داخل ملف `nginx.conf`:
- **منع الهجمات الخفية (Clickjacking)** عبر ترويسة `X-Frame-Options: DENY`.
- **منع التزييف واستنشاق المحتوى (MIME Sniffing)** عبر ترويسة `X-Content-Type-Options: nosniff`.
- **حماية مسار التوجيه (Referrer Protection)** عبر ترويسة `Referrer-Policy: strict-origin-when-cross-origin`.
- **سياسة أمان المحتوى الصارمة (CSP)**: تم صياغتها لتسمح للاتصالات الخارجية الضرورية فقط بالعمل (مثل Supabase، وOpen-Meteo، وOpenStreetMap، ومخدمات تلاوة القرآن الصوتية) مع حظر المصادر الخارجية غير الموثوقة تماماً.
- **سياسة ضغط البيانات (Gzip Compression)**: مفعّلة لتسريع تحميل أصول الويب وتقليل نقل البيانات بأكثر من 60%.
- **استراتيجيات التخزين المؤقت الذكية**:
  - الأصول الثابتة (JS, CSS, الصور) يتم تخزينها لمدة عام كامل (`Cache-Control: public, max-age=31536000, immutable`) معتمدة على تقنية الـ Hash لأسماء الملفات في Vite.
  - ملفات الإعدادات والصفحة الرئيسية يتم تصفير كاش التخزين الخاص بها لضمان التحديث اللحظي الفوري لأي إصدار جديد.

## 🚀 كيفية التشغيل محلياً (Local Run)

للحصول على نسخة تعمل محلياً بنفس بيئة السيرفر الحقيقية:

### 1. بناء الحاوية
```bash
docker build -t smarthub-app .
```

### 2. تشغيل الحاوية
```bash
docker run -d -p 8080:8080 --name smarthub smarthub-app
```

الآن، يمكنك تصفح التطبيق مباشرة عبر: `http://localhost:8080`

### 3. التحقق من حالة الصحة (Health Status)
```bash
docker ps
```
ستلاحظ ظهور كلمة `(healthy)` بجانب الحاوية كدليل على عمل خادم Nginx بكفاءة مطلقة واستجابته للطلبات.

## 🎛️ النشر والتشغيل باستخدام Docker Compose

إذا كنت ترغب في نشر التطبيق في سيرفر الإنتاج مع خدمات أخرى أو مع Supabase محلياً، يمكنك استخدام ملف `docker-compose.yml` التالي كقاعدة أساسية:

```yaml
version: '3.8'

services:
  smarthub:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: smarthub_app
    ports:
      - "80:8080" # ربط المنفذ 80 الخارجي بمنفذ الحاوية الآمن 8080
    environment:
      - VITE_SUPABASE_URL=https://your-project.supabase.co
      - VITE_SUPABASE_PUBLISHABLE_KEY=your-anon-key
    restart: always
    healthcheck:
      test: ["CMD", "wget", "--no-verbose", "--tries=1", "--spider", "http://localhost:8080/"]
      interval: 30s
      timeout: 5s
      retries: 3
```

لتشغيله:
```bash
docker compose up -d
```

## 📝 استكشاف الأخطاء وإصلاحها (Troubleshooting)

- **الملفات الساكنة لا تتحدث**:
  يتم تخزين الملفات الساكنة بكاش قوي. عند نشر نسخة جديدة، يتكفل محول Vite بتغيير أسماء ملفات الجافاسكريبت والـ CSS تلقائياً (Busting cache). إذا واجهت مشكلة، تأكد من تحديث صفحة المتصفح بالضغط على `Ctrl + F5` أو `Cmd + Shift + R`.

- **الاتصال بـ Supabase منقطع**:
  تأكد من تمرير متغيرات البيئة الصحيحة في ملف `.env` قبل عملية بناء الحاوية، حيث يقوم مجمع Vite بحقن متغيرات البيئة أثناء وقت البناء (Build-time) وليس وقت التشغيل (Run-time).
